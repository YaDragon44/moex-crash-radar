# R1.3.2 — Historical Coverage & Replay Dataset Gate

Status: CANDIDATE / QA

## Purpose
Prove that each candidate FUTOI instrument can be used in a point-in-time-safe 1H replay before any profitability test.

## Candidate universe
- MX — MOEX Russia Index futures
- Si — USD/RUB futures
- SR — Sberbank ordinary-share futures
- GZ — Gazprom ordinary-share futures
- LK — LUKOIL ordinary-share futures

The codes are MOEX derivatives underlying codes. Inclusion in the strategy universe is NOT assumed; each instrument must pass the historical FUTOI coverage audit.

## Admission gate
An instrument is admitted to replay only when:
1. 1H price bars exist for the requested period.
2. Complete FIZ+YUR FUTOI pairs exist.
3. FUTOI uses SYSTIME as availability time.
4. point_in_time_violations = 0.
5. at least 60 unique trading days are present for the initial research slice.
6. point-in-time FUTOI coverage of the 1H decision bars is >= 90%.

Thresholds 60 days / 90% are QA admission thresholds, not trading optimization parameters.

## Alignment rule
For each closed 1H decision bar, use only the latest complete FIZ+YUR snapshot for which:

`max(FIZ.SYSTIME, YUR.SYSTIME) <= decision_timestamp`

Never align by MOMENT alone and never backfill a snapshot published after the decision timestamp.

## Replay output
Each admitted row must contain:
- decision_timestamp
- OHLCV
- source_moment
- source_available_at
- total_oi
- retail_net
- legal_net
- delta_total_oi
- delta_retail_net
- delta_legal_net

## Fail-closed policy
- Missing price -> N/A
- Missing FUTOI -> N/A/FAIL depending on coverage
- publication after decision timestamp -> FAIL
- coverage < 90% -> FAIL
- no synthetic values or forward-fill across the Quality Gate

## Next gate
Only instruments with READY replay coverage proceed to M0 -> M5 -> FULL ablation and OOS/walk-forward validation.
