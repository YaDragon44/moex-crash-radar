# VKCO Monitor R1.1 — Production Hardening

## Goal
Keep architecture minimal while adding production observability.

## Added
- Daily Telegram heartbeat at 10:00 MSK on weekdays (scheduled 07:00 UTC).
- Telegram alert if the production workflow fails.
- Manual `heartbeat` mode.
- Existing real MOEX, trigger logic, anti-duplicate state and tests preserved.

## Architecture
GitHub Actions → MOEX ISS → VKCO monitor → Telegram.

No VPS, Cloudflare, DB, Docker, broker API or auto-trading.

## Production gate
1. PR regression tests PASS.
2. Merge to main.
3. Main production run PASS.
4. Manual heartbeat smoke-test PASS.
5. Verify Telegram delivery.

## Known limitation
GitHub Actions cron is best-effort and may start late. The daily heartbeat confirms the monitor actually executed, but it cannot independently detect a scheduler outage if GitHub never starts the job at all. A truly independent watchdog would require a second platform and is intentionally out of scope to keep the architecture simple.
